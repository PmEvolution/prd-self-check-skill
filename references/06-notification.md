# 06 消息通知自查

> 适用：PRD 里涉及任何消息 / 通知 / 红点 / Push 时。
> 核心：围绕「谁需要知道、什么时候知道、需要知道什么、知道之后去哪」四问，逐项查。

## 检查清单（7 维）

- **01 消息事件**：哪些业务事件触发消息 / 操作完成是否通知 / 状态变化是否通知 / 是否遗漏重要事件 / 哪些情况明确不发
- **02 接收对象**：发给谁 / 是操作人还是被操作人 / 是数据所属人还是相关参与者 / 不同角色收到的是否不同 / 是否存在多人需收到 / 是否排除操作人自己
- **03 发送时机**：事件后立即发 / 状态变化后发 / 是否延迟发 / 是否定时发 / 多个事件连续发生怎么处理 / 什么情况不发
- **04 消息内容**：发生了什么 / 哪个对象变了 / 结果是什么 / 是否说明原因 / 用户能否一眼看懂 / 是否告诉下一步怎么做
- **05 通知方式**：站内消息 / Push / 短信 / 微信 / 邮件 / 红点角标 / 是否多个渠道同时发
- **06 消息跳转**：点击进哪个页 / 是否进具体业务详情 / 对应数据还存在吗 / 用户是否还有权限查看 / 数据已删怎么办 / 状态已变怎么办
- **07 消息状态**：已读未读怎么处理 / 是否需红点 / 是否需未读数量 / 是否支持全部已读 / 列表按什么顺序 / 消息是否需分类

## 最后检查 4 问

1. 谁需要知道？
2. 什么时候知道？
3. 需要知道什么？
4. 知道之后去哪？

> 例子锚点（订单状态变化）：事件「已发货」→ 谁「用户」→ 何时「商家发货成功」→ 什么「你的订单已发货」→ 方式「站内/Push」→ 去哪「订单详情」。
