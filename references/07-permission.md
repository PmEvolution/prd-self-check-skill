# 07 权限自查

> 适用：PRD 涉及多角色、数据范围、操作受限时。
> 核心：围绕「谁能看、谁能做」，不做偏技术的 RBAC 权限设计。把「角色 × 数据 × 操作」对一遍，权限问题通常就显形了。

## 检查清单（7 维）

- **01 角色范围**：有哪些用户角色 / 不同角色权限是否不同 / 是否含管理员普通用户等特殊角色 / 是否遗漏某类用户 / 新增角色后是否需补权限
- **02 查看权限**：谁可以看到页面 / 谁可以看到这条数据 / 不同角色看到的内容是否不同 / 是否有只能看部分信息的角色 / 无权限时页面怎么处理
- **03 操作权限**：谁可以新增 / 编辑 / 删除 / 提交审核发布 / 不同角色操作权限是否不同 / 无权限时还能看到操作入口吗
- **04 数据范围**：能看到全部还是部分数据 / 是否只能看自己的 / 能否看下属团队数据 / 不同角色数据范围是否不同 / 数据范围变化后页面是否同步
- **05 权限变化**：角色变化后权限是否同步 / 权限收回后还能继续操作吗 / 权限新增后是否立即生效 / 已进入页面但权限变了怎么办 / 权限变化后原数据还能访问吗
- **06 无权限处理**：页面是否允许进入 / 按钮隐藏还是置灰 / 是否提示无权限 / 用户能否理解为什么不能操作 / 无权限时是否有替代操作
- **07 权限一致性**：列表和详情权限是否一致 / 页面入口与实际操作权限是否一致 / 前端展示与实际业务权限是否一致 / 同类功能权限规则是否一致 / 有无「看得到但不能操作」的异常

## 最后检查 5 问

- 谁能看？
- 谁能做？
- 能看哪些数据？
- 没有权限怎么办？
- 权限变化后怎么办？

## 判断方法（表格锚点）

| 角色 | 能看什么 | 能新增 | 能编辑 | 能删除 | 能审核 |
|------|----------|--------|--------|--------|--------|
| 普通用户 | 自己的数据 | 可 | 可 | 可 | — |
| 运营人员 | 全部数据 | — | 可 | — | 可 |
| 管理员 | 全部数据 | 可 | 可 | 可 | 可 |
